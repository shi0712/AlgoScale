# 点数接力对局：出题者题解

本题采用本对话确认的现场子集递推，时间 O(n2^m+nm)，额外空间 O(2^m+nm)，不使用预存答案。n 始终表示花色数，m 表示点数数。

这是相对公开逐子集逐花色逐点数方法 O(nm2^m) 的已验证改进，不宣称指数因子已经得到下界证明，也不宣称目前全局最优。原题来源为 QOJ 3743 J。

### 好点数集合刻画整个游戏

称点数集合 S 为好集合，如果防守方只用 S 中的牌，能为进攻方所有 S 中的牌安排互不重复的、能击败它的防守牌。

若开始牌点数属于某个好集合，防守方按这个固定匹配应答。双方新打出的牌点数始终在 S 中，防守方不会先无牌可用，故获胜。

反过来，如果一局最终是进攻方无法出牌而输，棋盘已出现点数集合 S 的所有进攻牌都已打完，各自都被一张不同的 S 内防守牌覆盖，故 S 是好集合。若开始牌不属于任何好集合，这种结束情况不可能发生，进攻方必胜。因每次耗牌，游戏必终止。

因此只需把所有好集合按位 OR。开始牌点数不在这个并集中的全部进攻牌，计入答案；相同花色和点数的多张牌仍分别计数。

### 一个花色的全部子集 O(2^m)

对同花色匹配，防守牌必须点数严格更大。按点数从大到小处理，先用之前累积的高点防守牌匹配当前进攻牌，再把当前防守牌放入池中。因此同点数防守牌不能错误地匹配当前攻击。

定义 `balance[S]` 为 S 中防守牌数减进攻牌数，`need[S]` 为完整匹配所需的最少额外无限高牌数，即所有前缀的最大缺口（与 0 取最大）。取 S 中最低点数 r，R=S\{r}，有

```
balance[S] = balance[R] + defender[r] - attacker[r]
need[S]    = max(need[R], attacker[r] - balance[R])
```

空集两者均为零。使用最低位找到 r，R<S，所以顺序枚举掩码即可 O(1) 转移。need 等于该花色内部无法匹配的最少进攻牌数，这也由按高点到低点的嵌套邻接/Hall 前缀约束直接得到。

对王牌花色，`need[S]` 必须为 0，因为其他花色的王牌也不能打它；剩余可跨花色使用的牌数为 balance[S]。对普通花色，need[S] 必须由剩余王牌支付。于是

\[
S\text{ 好}\iff
\text{所有王牌花色 need}=0,\quad
\sum_{王牌花色}balance\ge\sum_{普通花色}need.
\]

每个花色顺序复用 balance 和 need 数组，仅保留各集合总盈余和是否存在王牌缺口。时间 O(n2^m+nm)，空间 O(2^m+nm)。最大牌数在有符号 64 位范围内；不能用 32 位累计。


### 扩大到 n≤100 后的实现审计

只对 m≤18 取位掩码，最大 1<<m 为 262144；不会对 n=100 移位。花色标记和两份牌数矩阵按 n、m 动态分配。单花色 balance、need 的绝对值最多为 18×10^12；总盈余、总缺口与答案不超过 100×18×10^12=1.8×10^15，安全地位于有符号 64 位范围内。所有牌数、递推净额和答案均用 long long。

ctz 仅对从 1 开始的非零掩码调用。每个花色处理时，mask 的前驱严格小于 mask，故复用 balance/need 数组也会引用当前花色已经更新的状态；空集状态保持为零。标准程序不递归。空间在 256 MB 内有充足余量。

复杂度在 64 位整数加减比较及 32 位非零掩码最低位定位均为常数时间的 word-RAM 模型下计算。每个花色做 2^m−1 次常数工作，最终 OR 及统计起手次数也已计入上界。

### 本次独立验证

`brute.cpp` 显式枚举双方每张物理牌的出牌选择，记忆化真实游戏 minimax，最多每方 8 张牌。已穷举 n,m∈{1,2}、每个牌数为 0/1 的全部合法非空双手和王牌配置，共 956 例；另测 600 个随机小牌局。又用逐子集直接贪心对照 400 个大牌数随机实例，并对全部 20 个正式点核对输出。所有正式点均通过花色置换等价验证和 ASan/UBSan。具体记录见 ../records/。

`slow.cpp` 从最高点数开始直接模拟匹配池，不使用子集间递推；它包含王牌失败即退出、已经覆盖全部起手点数则退出等合理提前结束，编译参数与标准相同，不人为拖慢。
